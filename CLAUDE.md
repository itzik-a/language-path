# Language Path

My language-learning web app (React, built with Vite, hosted on GitHub Pages), used on a MacBook and an iPhone (installed to the Home Screen), for **Japanese, Polish, Arabic (MSA), Greek (modern), Portuguese (European), Russian, German and Dutch (intermediate), and Spanish, French and Italian (all three advanced: conversation first)**: spaced-repetition cards (FSRS), stories at my level, listening, and conversation practice with Claude. See `PLAN.md` for the research behind it, the concepts, milestones and decisions.

## How it's built

Vite + React 19 + TypeScript. Node 22 (`.nvmrc`). On this Mac `npm start` runs `nvm use` and then the dev server; `npm run dev` alone runs the local server; `npm run build` typechecks and builds into `dist/`; `npm test` runs Vitest (`tests/`).

- Routing is the URL hash (`src/lib/route.ts`): `#today`, `#review`, `#read`, `#read/<text id>`, `#talk`, `#talk/<chat id>`, `#words`, `#words/<word id>`, `#script`, `#script/<kind>`. The active language is per device (`src/lib/prefs.ts`), not in the URL; `<main>` is keyed by view + language.
- `src/types.ts`: the whole saved state (`AppState`): `words`, `cards`, `texts`, `chats`, `days`, `settings` (per language). Every list item has `id` + `updatedAt`; removals are soft (`deletedAt`). Dates are local `YYYY-MM-DD` (`src/lib/dates.ts`).
- Ids: a word's id is `wordKey(lang, lemma)` (`src/lib/langs.ts`; Arabic without harakat, every Latin, Greek and Cyrillic language lower-cased, Russian also without stress marks and with ё → е), so the same word added on two devices is one word. **Never change a lemma in `src/data/starter.ts`** once shipped.
- `src/state/store.ts`: state in memory, saved to IndexedDB (`idb`, db `languagePath`, key `state`; Safari caps localStorage at ~5 MB), loaded by `initStore()` before the first render; `update(fn)`, `replaceState()`, `useAppState()`. Open tabs stay in step through a BroadcastChannel. `src/state/actions.ts`: every change goes through here and stamps `updatedAt`; Undo toasts.
- Device-only prefs (`src/lib/prefs.ts`, localStorage `languagePath.device`): active language, voice + speed per language, the Claude key and model, the Google Cloud key and Google voice per language (`cloudVoice`: "" = device voice), a device id, reader toggles.
- Languages (`src/lib/langs.ts`): names, BCP 47 codes, direction, case, Arabic harakat stripping / folding, kana folding, kanji tests, `greekTranslit()` (Greek → Latin letters as it sounds, stress marked; used under Greek words and as every Greek word's `translit`), `russianTranslit()` (letter by letter, stress marked: молоко́ → molokó); `autoTranslit()` picks one. German (`nounCaps`) keeps noun capitals in lemmas (Hund; `lowerIfCased()` leaves them, ids still lower-case); `foldGerman()` lets ss / ae / oe / ue stand for ß ä ö ü in typed answers. Russian text carries stress marks (combining acute U+0301, as learner books do): `stripStress()` hides them when the "Stress marks" setting (the `harakat` field) is off, and speech always drops them. Portuguese is pt-PT everywhere (`strictRegion`: Portugal voices rank first). The voice picker names the region whenever voices come from more than one (Spanish: Spain, Mexico…). Spanish has no fixed variety: Claude follows the one named in my level description, else standard Spanish; French is France's unless the level text names another.
- Text in a target language always goes through `src/components/Lx.tsx` (`Term`, `Line`, `TokenText`): sets `lang` / `dir`, furigana from `src/lib/furigana.ts` (over kanji I don't know: `settings.lang.ja.knownKanji`), harakat on/off, Russian stress marks on/off, transliteration as under-ruby (Arabic from the token, Greek and Russian worked out on the device). Sentences are `Token[]` (`src/lib/tokens.ts`); whitespace and punctuation are tokens without a lemma so joining every `t` gives the text back.
- Starter content: `src/data/starter.ts` (words, with a small example markup parsed by `sentence()`), `src/data/seed.ts` (default settings, the first state), `src/data/stories.ts`.
- Voices (`src/lib/speech.ts`): the device's Web Speech voices, best first; one utterance at a time; `speakLines()` reads sentence by sentence; when other speech cuts in (a tapped word, one line) it calls `onBreak(i)`, and the reader (`views/Read.tsx`) then shows Paused and resumes from line i (Pause / Resume / Stop in its player). Japanese words are spoken from their kana reading (`sayWord()` in `src/lib/words.ts`) so lone kanji aren't misread. **Google voices** (`src/lib/cloudTts.ts`): Google Cloud Text-to-Speech with my own API key, called from the browser (`?key=`); `rankVoices()` puts Chirp 3 HD first, then Studio / Neural2, WaveNet, Standard; Arabic uses Google's `ar-XA`. MP3 clips are cached in IndexedDB (db `languagePath-tts`, store `clips`, up to 3000, not synced), synthesised at normal speed and slowed with `playbackRate`. They play through one `<audio>` element that the first tap unlocks (iOS). Any failure (offline, bad key, play refused) falls back to the device voice. `speakLines()` fetches the next line while one plays. `CLOUD_FIRST` (Arabic, Greek, Portuguese: no natural device or Chrome voice) get Google's best voice when a key is saved (`pickCloudDefaults()`). UI: the Google voice picker in Settings → Voice, the key in `components/GoogleSection.tsx`.
- Cards (`src/lib/srs.ts` wraps `ts-fsrs`, FSRS-6; state stored as plain numbers): kinds recog / listen / say / cloze / script. Card ids are `c_<word id>_<kind>` and `c_script_<char id>`. `src/lib/queue.ts` (pure, tested) picks what's next: learning steps due now, then reviews due today (one card per word a day: siblings wait), new cards mixed in every 4th answer, script cards capped at 12 new a day. Starting a word (`startNewWords`, daily `newPerDay`) creates recog + listen (+ cloze if it has an example); a "say" card is added once recognition stability ≥ `sayAfterDays`. Words not "learning" have their cards suspended (progress kept). Typed answers: `src/lib/check.ts` (romaji → kana via `src/lib/romaji.ts`; missing accents in Polish, Portuguese, Spanish, French, Italian, German, Dutch and Greek count as right, in cards and dictation (`foldAccents`); Greek and Russian typed in Latin letters are compared by transliteration (Greek also letter for letter and the usual Greeklish spellings; Russian ё as yo); Japanese romaji also against the word's romaji; œ / æ and accents on transliterations (kitāb) never count; Russian stress marks and ё are ignored; Arabic harakat ignored).
- Scripts (`src/data/scripts.ts`): kana, Arabic letters (four forms via ZWJ, Hebrew counterparts) and harakat, the Greek alphabet (Hebrew counterparts) and letter pairs, the Cyrillic alphabet in learning order (familiar, false friends, Greek cousins, new letters, vowels, signs; Hebrew counterparts by sound), sounds pages (`SOUNDS`: Polish, European Portuguese, Russian), minimal pairs. Char ids (`hira:ka`, `abc:ayn`, `grk:alpha`, `grx:ou`, `cyr:zh`…) never change.
- Texts: `src/data/stories.ts` (starter stories), `src/lib/coverage.ts` (share of known words, grammar words count as known), `src/lib/recorder.ts` (shadowing; nothing stored). New starter words / stories reach old copies through `withSeeds()` in `normalize()`.
- Claude (`src/lib/claude.ts`, loaded with `import()` only when used: the SDK is half the bundle): browser SDK with `dangerouslyAllowBrowser` and the device's key, `beta.messages.parse` with a Zod schema (`betaZodOutputFormat`), model from prefs (Opus 5.5 default), `fallbacks: "default"` except on Haiku, effort low (stories medium). Tokens come back with every field a string and are cleaned by `cleanSentence()`. Jobs: `writeStory`, `annotate`, `explainWord`, `suggestWords`, `chatTurn`, `reviewChat`. Tests run them against a fake fetch (`setFetchForTests`).
- Speech in: `src/lib/listen.ts` (the browser's SpeechRecognition; the keyboard's dictation is the fallback).
- Sync (`src/state/sync.ts`, the finance-path pattern): one private gist file `language-path.json`, an `Envelope` (`src/lib/crypto.ts`: AES-256-GCM, PBKDF2 key from a passphrase per device, the plaintext gzip-compressed first, `z: "gzip"`). localStorage `languagePath.gist` holds token, gist id, salt and derived key. Merge (`src/lib/merge.ts`): per item by `updatedAt`; card review logs are unioned. Backup (`src/lib/backup.ts`): the same envelope, sealed with the sync key or a backup passphrase. UI in `src/components/SyncSection.tsx`.
- Progress (`src/lib/progress.ts`): day logs (`d_<date>_<lang>_<device>`, per device so counts never collide) summed for minutes, streak and charts (`src/components/MiniBars.tsx`, one series, accent colour).
- Views (`src/views/`): `Today` (the four strands: cards, read & listen, talk, fluency; progress), `Review`, `Read` (library + reader), `Talk` (scenes + chat), `Words` (list with bulk "I know these", word page with its cards), `Script`. Sheets and shared UI in `src/components/` (`ui.tsx`: `Seg`, `Switch`, `Stepper`, `Field`, `Select`, `Sheet`; `SettingsSheet`; `LangSwitch`).
- Styling: plain CSS in `src/styles.css`, tokens in `:root` (the shared system of my apps, teal accent `#0E7490` / dark `#5BC8E0`). Japanese and Arabic get their own font stacks (`.lx-ja`, `.lx-ar`).
- **Theme**: System / Light / Dark per device (`src/lib/theme.ts`, localStorage "languagePath.theme", nothing stored = System), chosen in settings (`components/ThemePicker.tsx`). It sets `<html data-theme="light|dark">`; an inline script in `index.html` does it before the first paint. Dark tokens are `:root[data-theme="dark"]`, a dark-only rule is `:where(:root[data-theme="dark"]) .x { … }` (same specificity as `.x`). Never use `@media (prefers-color-scheme: dark)` in CSS.
- PWA: `public/manifest.webmanifest`, `public/icon.svg`, full-bleed PNG icons in `public/icons/` (rendered from the SVG with headless Chrome + `sips`), `public/sw.js` (production only; network first for the page, cache first for hashed assets; never touches other origins).

## Rules for changes

- Design mobile-first (iPhone ~390 px), tap targets at least 44 px, safe-area padding. Below 768 px: top bar + bottom tab bar (4 tabs); from 768 px a sidebar. Check both widths, light and dark, and all eleven languages (Arabic is right-to-left; Japanese has furigana; Greek and Russian have transliteration under words; Spanish opens with ¿ ¡, which take no space after them; French and Italian elided words (j', l', un') are their own tokens and the next word follows with no space: `isElided()` in `src/lib/langs.ts`, used by `sentence()` and `cleanSentence()`). On the phone the language is chosen from a native select (`LangSwitch compact`); the sidebar lists every language.
- Colours only from the CSS tokens in `:root`; light and dark themes must both stay readable.
- New state fields must be optional in `normalize()` so older copies still load.
- Nothing about me leaves the device unencrypted except what a Claude request needs (the text of that job, my level description and known-word list) and, with a Google key, the target-language sentence being spoken (to Google Text-to-Speech). The Claude and Google keys stay on the device and out of the synced state.
- Claude calls: structured outputs only, every schema field required (use "" for "none"); keep the job's request shape tested in `tests/claude.test.ts`.
- Run `npm test` and `npm run build` after edits; both must pass.
